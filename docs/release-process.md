# Release process

1. Make the change, add focused tests, and run `npm run verify`.
2. Update `CHANGELOG.md`, then bump the version in both `package.json` and `package-lock.json`.
3. Build unsigned installers locally where the host supports them: `npm run make:mac` or `npm run make:windows`. Run `npm run size:check -- --platform=macos` or `npm run size:check -- --platform=windows`. The check rejects only a tiny installer stub (under 25 MiB), missing updater metadata, or an implausibly large artifact (over 2 GiB); it must never be satisfied with padding.
4. Tag the matching commit as `v<version>` and push it to the Tasko Desktop GitHub repository. The workflow uses `macos-14` for the x64 DMG and `windows-latest` for the x64 NSIS installer. It verifies the bundled app boundary, verifies update metadata, silently installs the Windows build, blocks outbound networking for its exact installed executable, verifies it launches offline, then uninstalls it before gathering both platform artifacts.
5. The release job publishes a GitHub **prerelease** only after both platform jobs succeed. It uploads the installer, updater YAML, blockmap, `SHA256SUMS.txt`, and `TASKO_RELEASE_STATUS.json`. The latter two are generated from the exact uploaded files; do not edit them by hand.
6. The workflow marks each installer `signed` only after it verifies a Developer ID identity and `codesign --verify --deep --strict` integrity check (macOS), or a valid Authenticode signature (Windows). Without those credentials, it publishes an explicitly unsigned development build. This status does not attest to macOS notarization; validate notarization separately before changing the channel to a public non-prerelease.
7. Configure the optional website cache notification by adding `TASKO_RELEASE_REVALIDATE_URL` and `TASKO_RELEASE_REVALIDATE_SECRET` to the desktop repository's GitHub Actions secrets. The release workflow posts to that URL with the secret in `x-tasko-release-revalidate`; the website independently refreshes release data within 60 seconds if notification is unavailable.

Updates use GitHub Releases through electron-updater. The app checks at launch and every four hours, downloads in the background, and presents an install-on-quit banner. Every database migration makes a backup first.
